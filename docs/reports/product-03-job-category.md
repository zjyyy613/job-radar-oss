## 3. 分类规则

实现在 `src/lib/radar/job-category.ts`（纯函数、无网络、无模型、无数据库、版本号 `job-category-v1`）。**规则顺序即语义**，关键设计：

1. **非岗位公告先隔离**（`招聘公告`/`校园招聘公告`/`宣讲会` 等）→ `其他>非岗位公告`，从不强行归类。
2. **职能中心词优先于领域关键词** → `AI产品经理`=产品、`视觉策略设计师`=设计、`AI产品运营`=运营；AI 不会劫持产品/运营/设计。
3. **工程与制造先于技术研发**并各带否决词 → `转向系统工程师`=汽车与整车，而 `软件开发工程师（机器人方向）`=软件开发、`无人机仿真软件研发`=软件开发。
4. **销售/市场词带技术否决词** → `广告算法工程师`、`算法工程师（推广/搜索/广告方向）`=算法与AI，而 `游戏市场营销实习生`=市场营销。
5. **子串碰撞守卫** `(?<!机器)人事` → `机器人事业部-具身大模型算法研究员`=算法与AI，不会命中人事。
6. **法务先于技术** → `专利工程师`=法务与合规（不是工程师）。
7. **公司无关**：规则文本中不含任何公司名；同一标题在任何来源下归类相同（模块只接收标题，没有公司入参）。
8. **标题不完整不猜**：26 类模式标记为**暂定分类**，界面显示「岗位类别待核实」。这与资格判断的「需要确认」是两件事，**不得混用**。

## 5. 计数语义与交互约定

- **计数来源**：由当前筛选结果实时计算（`countCategories`），**不写死快照数字**，新岗位自动纳入。
- **计数口径**：显示的是**排除类别筛选本身、其余筛选（关键词/地点/公司/资格）之后的岗位量**——即"点进去会看到多少条"，因此数字与列表恒等；菜单成员资格由数据集决定（`available`），所以有真实岗位的类别不会因为当前筛选而消失。
- **选择一级即筛选**：点击一级立即生效（不必先选二级），弹层保持打开以便继续收窄；点击二级或「全部X」后弹层关闭，结果立即可见。
- **URL**：新增独立 `cat`（一级 id）与 `sub`（二级 id），**不改动也不复用 `role` 的关键词语义**；与 q/city/company/status/sort 组合；前进后退、详情预览与完整详情返回均保留分类状态。
- **无效链接**：未知 id 被忽略并显示「该岗位类别链接已失效，现按全部类别显示」+「清除类别」；`cat` 与 `sub` 父子不一致时只保留有效的一级，并同样给出提示（**不重写用户 URL**，因为地址栏保留了用户原本的错误，便于其理解发生了什么）。
- **默认列表**：不选类别时 `其他>未分类` 与 `其他>非岗位公告` 仍在列表中，不会消失。

## 6. 已知边界（需要后续独立复核）

1. **暂定分类 30 条**：标题本身无法确定职能（如理想 `产品专家实习生` 很可能是零售销售、`销售产品实习生`、`产品布道师`、`设计数据工程师`、京东各单词式标题）。它们保留暂定类别并显示「岗位类别待核实」，**没有为了覆盖率而猜测**。
2. **两处已知歧义未强行统一**：美团 `KA酒店运营-解决方案实习生`（运营 vs 售前与解决方案）、OPPO `战略文案经理`（战略 vs 文案/市场）。
3. **规则只依据标题**：不读取 JD 正文，因此 `published_at`/JD 变化不会改变分类；若后续要用 JD 提升精度，应作为独立任务并保留标题规则的版本号。
4. **浏览器验收是组件级**：本工作区缺 `.env.local`，`/radar` 无法读取真实数据，因此用临时 harness 路由驱动**真实 `RadarClient` + 真实 472 条标题**；harness 中地点按公司合成、gates 为空。**这不等于真实页面端到端验收**（真实页面的地点/资格维度已在 PRODUCT-02.1 单独验收）。harness 与生成数据在提交前已删除。
5. **快照文件不入库**：`Job_Radar_PRODUCT03_472_titles_2026-10-16.json` 与 `.verification/product03/` 均未提交（后者已被 gitignore）。因此**全量 472 条不变式检查不在 CI 内**；入库的是内嵌 81 条金标 + 6 条计数一致性测试。若希望 CI 覆盖全量，需要把快照（或脱敏后的标题列表）作为测试 fixture 提交，属于新的授权决定。
